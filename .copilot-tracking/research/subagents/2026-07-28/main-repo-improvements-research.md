## 1) Current-State Inventory

### Repository workflows and orchestration

Root pipeline is heavily GitHub Actions-driven, chained by workflow events:

- 0-france-exp.txt -- Add-Version - Create france.txt
  - .github/workflows/0-france-exp-add-version.yml
  - Trigger: push on main when france-exp.txt changes.
  - Responsibilities: inject *version header into france-exp.txt, generate france.txt, commit both.

- 1-Validate_Add_Version_Convert
  - .github/workflows/1-validate-convert-push.yml
  - Trigger: push on main for france.txt and workflow_run from workflow 0.
  - Responsibilities: validate france.txt, generate france.geojson, re-add version to france.txt, generate france.cub, dispatch airspace-update.

- 2-create_openair_standard
  - .github/workflows/2-create-openair-standard.yml
  - Trigger: workflow_run from workflow 1.
  - Responsibilities: convert france.txt -> france_openair_standard.txt, validate standard file, dispatch event to another repo.

- 3-create-copies-with_date
  - .github/workflows/3-create-copies-with_date.yml
  - Trigger: workflow_run from workflow 2.
  - Responsibilities: create timestamped file copies, mutate README.md and README.en.md dated links, commit all changes, dispatch update-pages-event.

- 4-Copy-To-Planeur.net-FTP
  - .github/workflows/4-copy-planeur.net.yml
  - Trigger: workflow_run from workflow 3.
  - Responsibilities: FTP deploy selected files.

- 5-update-eaip-url
  - .github/workflows/5-update-eaip-url.yml
  - Trigger: scheduled weekly Thursday plus manual dispatch.
  - Responsibilities: run npm script to refresh AIP/ENR links and open PR automatically.

Additional workflows:

- validate-branch
  - .github/workflows/validate-branch.yml
  - Validates france.txt or france-exp.txt on feature/*, autogenerated/*, PR, or manual dispatch.

- 98-france-exp.txt -- Validate
  - .github/workflows/98-france-exp--validate.yml
  - Separate PR/manual validation flow for france-exp.txt.

- zsm-generate-pr
  - .github/workflows/zsm-generate-pr.yml
  - Manual workflow to fetch/convert ZSM source and create autogenerated branch.

- jekyll-gh-pages
  - .github/workflows/jekyll-gh-pages.yml
  - Triggered by repository_dispatch update-pages-event to publish pages.

- 100-france-exp.txt -- GDrive and 1000-Ludovic Private Actions
  - .github/workflows/100-france-exp--Gdrive.yml

## 2) Concrete Pain Points with Evidence

### A. Workflow duplication and drift risk

- Repeated parser install/build blocks across workflows increase maintenance effort and runtime:
  - .github/workflows/1-validate-convert-push.yml:51
  - .github/workflows/2-create-openair-standard.yml:56
  - .github/workflows/98-france-exp--validate.yml:41
  - .github/workflows/validate-branch.yml:76

- Repeated validation command invocation in same step (run command once, then again for capture), doubling runtime:
  - .github/workflows/1-validate-convert-push.yml:60-61
  - .github/workflows/98-france-exp--validate.yml:50 plus immediate SCRIPT_OUTPUT capture line
  - .github/workflows/validate-branch.yml:85-86
  - .github/workflows/2-create-openair-standard.yml equivalent pattern in validation step.

### B. Fragile orchestration and event-chain complexity

- Deep workflow_run and repository_dispatch chaining creates opaque failure paths and harder troubleshooting:
  - .github/workflows/1-validate-convert-push.yml:14
  - .github/workflows/2-create-openair-standard.yml:8 and 110
  - .github/workflows/3-create-copies-with_date.yml:7
  - .github/workflows/jekyll-gh-pages.yml:5

- A display step references needs.validate-airspace output inside a workflow/job where that need does not exist, indicating likely dead/incorrect diagnostic output:
  - .github/workflows/2-create-openair-standard.yml:78

### C. Deprecated Actions syntax still present

- ::set-output is deprecated and still used:
  - .github/workflows/zsm-generate-pr.yml:25-27

### D. Commit-loop and race-condition susceptibility

- Workflows call git pull in mutation stages before auto-commit, increasing race surface and non-determinism:
  - .github/workflows/0-france-exp-add-version.yml:39
  - .github/workflows/1-validate-convert-push.yml:131, 162

- Multiple auto-commit stages with shared commit message output typo LAST_COMMIT_MESSSAGE repeated across workflows can propagate brittle conventions:
  - .github/workflows/0-france-exp-add-version.yml:42
  - .github/workflows/1-validate-convert-push.yml:35, 74, 134, 165
  - .github/workflows/3-create-copies-with_date.yml:116

### E. Documentation/data naming inconsistencies

- README.md uses france-openair-standard.txt label while generated file name and links use france_openair_standard.txt:
  - README.md:22
  - README.en.md:18 (uses underscore form)

- Static AIP France links in both readmes require scheduled replacement, indicating docs are source-like data:
  - README.md:11
  - README.en.md:11

### F. Regex-based README mutation is brittle

- Date update relies on broad sed regex replacements in CI and shell script, which can unintentionally alter unrelated content if format changes:
  - bin/create_copies.sh:60-62
  - .github/workflows/3-create-copies-with_date.yml:101-103

### G. Utility script quality issues in src/findLines.js

- Script logs both resolved lines and unresolved Promise variable, reducing clarity and usefulness:
  - src/findLines.js:23-24

### H. Branch validation overlap

- Two separate validation workflows for branch/PR contexts can drift and duplicate maintenance:
  - .github/workflows/validate-branch.yml
  - .github/workflows/98-france-exp--validate.yml

## 3) Prioritized Opportunities

### Quick Wins (low-medium effort, high value)

1. Replace deprecated ::set-output with $GITHUB_OUTPUT in zsm workflow.
2. Fix invalid diagnostic reference in 2-create-openair-standard display step.
3. Remove duplicate validator command invocations in each validation step.
4. Normalize naming in docs to france_openair_standard.txt consistently.
5. Tighten update regex logic or replace with deterministic parser-based replacement for README date tokens.
6. Harmonize action versions (e.g., checkout v4 consistently where possible).
7. Clean src/findLines.js behavior or move to a proper npm utility script.

### Medium/Longer Efforts (higher impact, higher coordination)

1. Introduce reusable workflow(s) or composite action for validation and parser setup.
2. Collapse fragmented workflow chain (0->1->2->3->4 plus dispatch) into fewer explicit stages with artifacts.
3. Define deterministic artifact strategy: either commit snapshots or publish as release assets/pages artifacts, not both by default.
4. Introduce concurrency groups and idempotency guards to prevent concurrent mutation pushes on main.
5. Refactor docs update pipeline to generate download table from structured metadata instead of in-place sed mutation.
6. Clarify lifecycle for private integration workflows (GDrive/private repo dispatch) and ownership boundaries.

## 5) Risks and Dependencies

### External dependencies

- Heavy reliance on external services and repositories:
  - SIA web pages availability and format stability (src/extract-eaip-links.js)
  - FTP availability and credentials (.github/workflows/4-copy-planeur.net.yml)
  - GDrive credentials and API action stability (.github/workflows/100*.yml)
  - External converter repos checked out at runtime (.github/workflows/2-create-openair-standard.yml, zsm-generate-pr.yml)

### Operational risks

- Main-branch auto-commits from multiple workflows raise contention and traceability challenges.
- Event-chain failures may be silent or hard to correlate across workflows.
- Regex-based README rewriting can accidentally modify human-authored text.
- Timestamped committed snapshots can increase repository churn and history noise.

### Governance dependencies

- Decisions required on artifact retention policy (Git history vs release assets vs pages-only).
- Decisions required on whether automation should remain mutation-heavy (auto-commit) or shift to PR-based updates.
